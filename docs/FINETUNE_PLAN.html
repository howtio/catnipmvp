🧠 二、微调原理

2.1 为什么要微调而非换模型？

❌ 当前 1.5B 的问题
  • 不知道何时调用工具（准确率 ~40%）
  • 依赖 heuristic 关键词匹配补救
  • heuristic 未覆盖的输入全部失败
  • 安全对齐过于保守（拒绝情书等合法请求）
✅ 为什么 LoRA 微调
  • 保留 1.5B 的推理速度（比大模型快 10x）
  • 仅需 ~$3 生成训练数据
  • Colab 免费 T4 可跑，45 分钟完成
  • heuristic 兜底：模型退化时不造成灾难

  "You are a coding agent...",
  PLATFORM_HINT,

  "Task: 帮我写一个html然后打开",
  "Allowed tools:\n- write_file (medium): Write a single file...",
].join("\n\n")

       ▼
// generateObject → 模型输出 JSON
{
  plannedToolCalls: [
    { name: "write_file", args: { path: "workspaces/demo/task_output.html", content: "..." } },
    { name: "open_browser", args: { path: "workspaces/demo/task_output.html" } }
  ],
  finalAnswerPrompt: "已创建并打开 HTML 文件。"
}
       │
       ▼
// normalizePlannedCalls → PlannedToolCall[]
// 过滤未知工具，规范化参数默认值
       │
       ▼
// wrapper.ts: 逐工具执行
for (const plannedCall of plan.plannedToolCalls) {
  await executeToolCall(plannedCall)
}
       │
       ▼
// Executor: 权限校验(guard.ts) → 执行工具(tools.ts) → 返回结果
