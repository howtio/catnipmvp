## 2026-05-18 / Phase 1 / 完成内存队列状态流转与等待机制

### 当前目标

让 Queue 不仅能 FIFO 排队，还能为 Gateway 和 Worker 提供最小可观察状态流转。

### 本次完成

- 以任务表保存队列内任务快照
- 增加 `waitForTask` 通知式消费接口
- 增加 `waitForCompletion` 完成等待接口
- 支持在状态变更时补充时间戳和错误信息

### 当前状态

- 已完成：内存 FIFO、状态维护、任务等待通知
- 进行中：仅支持单进程内最小等待模型
- 未完成：持久化、超时、取消能力

### 风险与阻塞

- 当前 waiters 仅覆盖 MVP 单进程场景

### 下一步

- Phase 2 之后继续按需要补更细的状态观测字段

## 2026-05-19 / Queue / 增加动态状态订阅与排队位置

### 当前目标

让 Queue 不只提供“最终完成等待”，还要把排队中的动态状态暴露给 Gateway，支撑 CLI 显示等待位置和等待时间。

### 本次完成

- 任务增加 `updatedAt`
- 任务增加 `queueEnteredAt`
- 任务增加 `queuePosition`
- Queue 增加 `subscribe`
- Queue 快照增加 `queueDepth`
- Queue 快照增加 `pendingCount`
- 入队后立即广播 pending 快照
- 出队或派发后刷新后续任务位置
- 状态变化后统一广播最新快照
- 新增 Queue 订阅测试

### 当前状态

- 已完成：队列动态状态观测
- 进行中：仍是进程内订阅，不做持久化
- 未完成：取消、优先级、持久化 backlog

### 风险与阻塞

- 当前订阅器是内存实现，只覆盖单进程 MVP
- `pendingCount` 当前与 `queueDepth` 等价，后续若引入更多状态需重新定义

### 下一步

- 可继续补取消与优先级
- 或补更精确的 backlog 指标
