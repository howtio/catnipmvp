# Progress System

本目录用于让不同设备、不同会话、不同 Codex 连续接力开发，并保证进度记录能追溯到层级。

当前分层体系为 `01` 到 `10`，并在 `06` 与 `07` 之间插入 `06.5-memory`。

## 读取顺序

1. `CODEX_MASTER_REQUIREMENTS.md`
2. `docs/DEV_PROGRESS.md`
3. `docs/LOG.md`
4. `docs/progress/layers/*.md`

## 写入规则

- 总进度写入 `docs/DEV_PROGRESS.md`
- 每轮施工写入 `docs/LOG.md`
- 某一层有开发动作时，必须追加对应层日志
- 不覆盖旧记录，只追加

## 使用原则

- 先读再改，不允许跳过历史记录直接开发
- 先记目标，再动手实现
- 每次真实开发前都要先上传一个可回退备份，并记下分支名与提交号
- 发生阻塞、测试失败、回滚时必须即时追加
- 每次收尾都要确认 GitHub 上传已经完成；默认不得遗漏
- 每次 GitHub 上传都要在最终说明和 `docs/LOG.md` 中标记本轮改动部分
- 每次 `docs/LOG.md` 记录都要写本轮版本号
- 每次收尾都要检查是否需要回滚到上一版本，并记录判断结果
- 如果发生回滚，必须把实际复测命令写进最终说明
