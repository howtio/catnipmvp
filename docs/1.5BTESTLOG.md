## LoRA Fine-Tuning 方案 V2

### 目标

提升 qwen2.5:1.5b 的工具调用决策能力，使其在 heuristic 覆盖范围之外也能正确规划工具。

### 核心变化 (vs V1)

1. **训练数据格式**: 改用 OpenAI/BFCL 格式 (`name` + `args`，不含 `reason`)
2. **数据来源调整**: 减少 DeepSeek API 生成（格式可能不匹配），增加 heuristic 蒸馏 + 真实回放
3. **评估指标细化**: 按任务类型分项评估

### 训练数据格式

使用新的 OpenAI 兼容格式：

```json
{
  "instruction": "帮我写一个python代码是斐波那契数列",
  "output": {
    "plannedToolCalls": [
      {
        "name": "write_file",
        "args": {
          "path": "workspaces/demo/fibonacci.py",
          "content": "def fib(n):\n    a, b = 0, 1\n    for _ in range(n):\n        yield a\n        a, b = b, a + b\n\nif __name__ == '__main__':\n    for i, f in enumerate(fib(10)):\n        print(f'fib({i}) = {f}')"
        }
      }
    ],
    "finalAnswerPrompt": "已创建斐波那契数列 Python 文件"
  }
}
```

无工具场景：
```json
{
  "instruction": "你是谁",
  "output": {
    "plannedToolCalls": [],
    "finalAnswerPrompt": "我是 Catnip Agent，一个基于本地模型的 AI 助手。有什么可以帮助你的吗？"
  }
}
```

### 数据收集策略（更新版）

#### A. Heuristic 规则蒸馏 (主要, ~500条)
将现有 heuristic 规则转化为训练样本。每类生成 30-50 个变体：

| 任务类型 | 样本数 | 覆盖范围 |
|----------|--------|----------|
| 写代码（Python/JS/TS） | 50 | 斐波那契、排序、Hello World 等 |
| 写 HTML（含 + 打开） | 50 | 游戏、页面、工具页面 |
| 写文本（情书/诗/故事） | 30 | 绕过安全对齐的替代表述 |
| 搜索查询 | 30 | 搜索 + 浏览器搜索 |
| 打开浏览器/文件 | 30 | "打开"、"预览"、"运行" 变体 |
| Shell 命令 | 20 | git、npm、dir 等 |
| 无需工具 Q&A | 80 | 身份、问候、闲聊 |
| **边界案例** | **80** | 修改意图("改粉色")、删除、复合任务 |
| **元问题** | **30** | "你的json格式"、"你是什么模型" |

#### B. Heuristic 边界增强 (~200条)
针对当前 heuristic 未覆盖的失败模式：
- "改/修/删 + 文件" → write_file 或 patch_file
- "转html" → write_file
- 知识问答 → web_search fallback
- "你的xxx" 元问题 → 预设回答

#### C. 真实对话回放 (~100条)
从 logs/catnip-trace.jsonl 和测试记录中提取真实输入-工具序列对。

### LoRA 训练参数

```
基础模型: qwen2.5:1.5b
LoRA rank: 16
LoRA alpha: 32
LoRA target modules: q_proj, k_proj, v_proj, o_proj (all attention)
学习率: 2e-4

精度: 4-bit QLoRA (bitsandbytes)

```

### 训练流程

```
1. 数据准备
   ├── 编写 heuristic 样本生成脚本
   │   ├── 模板 + 随机化参数（路径、文件名、内容摘要）
   │   └── 输出校验（格式、参数合法性）
   ├── 边界案例人工标注
   │   ├── 收集 20 个 heuristic 无法处理的输入
   │   └── 人工标注正确的 tool plan
   └── 格式转换：确保所有样本使用 OpenAI JSON 格式

2. 训练环境
   ├── Google Colab (免费 T4 可跑 QLoRA)
   └── 推荐: Unsloth 框架

3. 训练
   ├── QLoRA 4-bit 量化
   ├── 500 steps
   ├── 验证集 loss 监控
   └── 导出 adapter 权重

4. 部署
   ├── 合并 LoRA 权重到 base model
   ├── 导出为 Ollama GGUF (通过 llama.cpp)
   └── 测试与现有 heuristic 的兼容性
```

### 评估方法

| 指标 | 测量方式 | 当前基线 | 预期目标 |
|------|----------|----------|----------|
| 工具调用准确率 | 100 条测试集，tool plan 是否匹配预期 | ~40% | ~70% |
| 参数正确性 | 工具参数是否合法 | ~50% | ~80% |
| 无工具场景准确率 | 不需要工具时是否返回空计划 | ~60% | ~85% |
| 端到端任务成功率 | 完整任务执行 | ~56% | ~70% |
| 安全拒绝率 | 情书/情歌类是否不应拒绝 | ~50% | ~20% |

### 预期收益

1. **工具决策**: heuristic 未覆盖的长尾任务也能正确路由
2. **内容质量**: 减少安全拒绝，提升生成内容可用性
3. **格式正确性**: 减少代码围栏、说明文字等噪声

### 风险

- **过拟合 heuristic**: 缓解方法为保留 20% 边界案例
- **灾难性遗忘**: 保留 30% 纯 Q&A 数据，使用低 rank
- **数据生成质量**: 使用自动化校验脚本过滤非法格式

## 附录: 失败模式分类

所有已知失败可归为 4 类：

### Class A: Heuristic 未覆盖 (优先级 P0)
- "改粉色"、"修文件"、"删文件"、"转html"
- 解法: 补充 heuristic 关键词 或 LoRA 微调

### Class B: 模型安全对齐 (优先级 P1)
- 拒绝情书/情歌/浪漫内容
- 解法: LoRA 微调覆盖安全行为，或使用 system prompt 绕过

### Class C: 模型能力不足 (优先级 P2)
- 复杂代码（贪吃蛇、俄罗斯方块）生成不完整
- 知识问答超时
- 解法: 换更大模型 (qwen3:1.7b+)

### Class D: 格式/后处理问题 (优先级 P1)
- HTML 内容包含 markdown 代码围栏
- .txt 文件不被识别为可打开的文件
- 解法: 增强 strip 逻辑，扩展 openable file 检测
