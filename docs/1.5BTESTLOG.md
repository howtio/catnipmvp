## 核心问题总结

### 1. 工具调用决策 (严重)
模型不知道什么时候该调工具。以下情况全部失败：
- "改粉色" → 没调 `patch_file`
- "删文件" → 没调工具（且无对应工具）
- "转html" → 没调 `write_file`
- 需要搜索的知识问题 → 没调 `web_search`

**现状**: heuristic 规则覆盖了常见模式，但规则之外的意图全部漏掉。

### 2. 生成内容质量 (中等)
- 简单代码（斐波那契）✅ 可用
- 简单文本（情书、情诗）✅ 可用
- 复杂代码（贪吃蛇游戏、俄罗斯方块）❌ 玩具级，不可用
- 安全对齐过于敏感，有时拒绝合理请求

### 3. 对话质量 (中等偏下)
- 回声问题：部分情感问题直接重复用户输入
- 中英混杂：偶尔用英文回答中文问题
- 知识截止：2024 年初知识，无法回答新信息

### 4. Working Memory 消费 (中等)
- "帮我打开它" ✅ 正确解析
- 但 .txt 文件不会注册为 openableHtmlPath，fallback 失败

## LoRA Fine-Tuning 方案

### 目标

提升 qwen2.5:1.5b 的工具调用决策能力，使其在 heuristic 覆盖范围之外也能正确规划工具。

### 核心思路

当前 1.5B 模型的问题不是**能不能生成工具调用格式**，而是**不知道什么时候该调**。训练数据应聚焦于"决策边界"：

```
用户输入 → 该调用哪个工具？参数是什么？什么时候不调工具直接回答？
```

### 数据格式

训练样本格式（Alpaca-style）：

```json
{
  "instruction": "用户的任务描述",
  "output": "工具调用计划或直接回答"
}
```

output 的格式与现有 `aiSdkPlanSchema` 一致：

```json
{
  "plannedToolCalls": [
    {
      "toolName": "write_file",
      "args": {"path": "workspaces/demo/hello.py", "content": "print('hello')"},
      "reason": "用户要求写一个 Python hello world"
    }
  ],
  "finalAnswerPrompt": "已经创建了 hello.py"
}
```

对于不需要工具的场景：
```json
{
  "plannedToolCalls": [],
  "finalAnswerPrompt": "我是 Catnip Agent，一个基于本地模型的 AI 助手。"
}
```

### 数据收集策略（3 种来源）

#### A. DeepSeek API 生成 (主要, ~1000条)
用 DeepSeek-v3 或类似大模型，对以下模板任务批量生成 tool plan：
- 写文件（代码、文本、HTML）~200条
- 搜索查询 ~100条
- 打开浏览器/URL ~100条
- Shell 命令 ~100条  
- 读文件 ~100条
- Git 操作 ~50条
- 复合任务（写+打开）~100条
- 无需工具的 Q&A ~150条
- 情感/闲聊 ~100条

#### B. heuristic 规则蒸馏 (~200条)
将现有 heuristic 规则转化为训练样本：
- 每个 heuristic 分支生成 10-20 个变体
- 覆盖边界情况（近似但不完全匹配关键词的输入）

#### C. 真实对话回放 (~100条)
从 `logs/catnip-trace.jsonl` 中提取用户真实输入和最终工具调用序列，人工审核后作为训练数据。

### LoRA 训练参数建议

```
基础模型: qwen2.5:1.5b
LoRA rank: 16
LoRA alpha: 32
LoRA target modules: q_proj, k_proj, v_proj, o_proj (all attention)
学习率: 2e-4
批次大小: 8 (gradient accumulation=2)
训练步数: 500-1000
精度: 4-bit QLoRA (bitsandbytes)
数据集大小: ~1000-1500 条
验证集: 10%
最大序列长度: 4096 tokens
```

### 训练流程

```
1. 数据准备
   ├── 用 DeepSeek API 生成批量 tool plan 数据
   ├── heuristic 规则蒸馏
   ├── 真实对话回放
   └── 人工抽检质量 (~20%)
   
2. 训练环境
   ├── 可选: Google Colab (免费 T4 可跑 QLoRA)
   ├── 可选: 本地 RTX 3060+ (12GB+ VRAM)
   └── 推荐: Unsloth 框架 (训练速度 2x)

3. 训练
   ├── QLoRA 4-bit 量化
   ├── 500 steps
   ├── 验证集 loss 监控
   └── 导出 adapter 权重

4. 部署
   ├── 合并 LoRA 权重到 base model
   ├── 导出为 Ollama GGUF (通过 llama.cpp)
   └── 或直接用 transformers 加载 adapter + base
```

### 评估方法

| 指标 | 测量方式 | 当前基线 |
|------|----------|----------|
| 工具调用准确率 | 100 条测试集，模型输出的 tool plan 是否匹配预期 | ~40% |
| 参数正确性 | 工具参数是否合法（路径、query 等） | ~50% |
| 无工具场景准确率 | 不需要工具时是否返回空计划 | ~60% |
| 端到端任务成功率 | 写文件→内容是否合理 | ~56% |

### 预期收益

- 工具调用准确率从 ~40% 提升到 ~70%+
- 减少对 heuristic 规则的依赖
- 长尾任务（不在 heuristic 关键词中的）也能正确路由
- 减少"回声"和"中英混杂"等对话质量问题（如果训练数据包含高质量 Q&A）

### 风险

- **过拟合 heuristic 规则**: 模型可能只学会现有模式，对新类型任务无泛化
  - 缓解: 训练数据包含 20% 边界案例和否定案例
- **灾难性遗忘**: LoRA 微调后原有对话能力下降
  - 缓解: 保留 30% 纯 Q&A 数据，低 rank
- **数据质量**: DeepSeek 生成的 tool plan 可能不符合 catnip 的 schema
  - 缓解: 人工抽检 + 格式校验脚本
